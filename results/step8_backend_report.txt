1. BACKEND FRAMEWORK & ARCHITECTURE
--------------------------------------------------------------------------------
Framework: FastAPI with Uvicorn ASGI server.
Design Pattern: Layered Service-Oriented Architecture (SOA):

  Client / Future Frontend
             ↓
     FastAPI (backend/main.py)
             ↓
    Services (backend/services/)
      ├── model_service.py        (Singleton model holder, metadata, forward pass)
      ├── prediction_service.py   (Validation, deterministic preprocessing, formatting)
      └── explanation_service.py  (Grad-CAM heatmap, overlay, base64 visualization)
             ↓
    Core ML Modules (src/)
      ├── src/config.py           (Single source of truth for paths, class mappings)
      ├── src/preprocessing.py    (LetterboxResize to 224x224, zero padding)
      └── src/explain.py          (GradCAMExplainer targeting 'top_activation')

Zero duplication of preprocessing logic or class mappings:
- Class IDs strictly mapped: 0=glioma, 1=meningioma, 2=pituitary, 3=notumor.
- Both predict and explain endpoints directly import and reuse src/ modules.

--------------------------------------------------------------------------------
2. MODEL LOADING STATUS
--------------------------------------------------------------------------------
Strategy: Lifespan Context Manager (FastAPI lifespan).
Loading Mode: Loaded ONCE during application startup into memory.
Persistence: Kept resident in RAM/VRAM across all incoming HTTP requests.
Model Checkpoint: models/best_brain_tumor_model.keras (EfficientNetB0, 4,054,695 params).
Startup Validation: Throws explicit RuntimeError if checkpoint is missing or corrupted.
Status: OPERATIONAL (Load time ~0.76s on Apple Silicon MPS / CPU).

3. ENDPOINTS CREATED
--------------------------------------------------------------------------------
1. GET /health
   - Purpose: Service liveness and model readiness probe.
   - Status: 200 OK
   - Response Schema: {"status": "ok", "model_loaded": true}

2. GET /model-info
   - Purpose: Model architecture metadata, input shapes, classes, and research scope.
   - Status: 200 OK
   - Response Schema:
     {
       "model": "EfficientNetB0",
       "input_shape": [224, 224, 3],
       "classes": ["glioma", "meningioma", "pituitary", "notumor"],
       "test_accuracy": 0.9281,
       "purpose": "educational/research image classification"
     }

3. POST /predict
   - Input: Single uploaded image file (multipart/form-data, max 10MB).
   - Supported Formats: JPG/JPEG, PNG.
   - Processing: In-memory PIL decoding -> LetterboxResize (224x224) -> Model forward pass.
   - Response Schema:
     {
       "predicted_class": "glioma",
       "confidence": 0.782,
       "probabilities": {
         "glioma": 0.782,
         "meningioma": 0.173,
         "pituitary": 0.011,
         "notumor": 0.034
       }
     }
   - Metric Nomenclature: "model confidence score" (Strictly non-diagnostic).

4. POST /explain
   - Input: Single uploaded MRI scan (multipart/form-data, max 10MB).
   - Supported Formats: JPG/JPEG, PNG.
   - Processing: In-memory PIL decoding -> LetterboxResize -> Grad-CAM on 'top_activation' ->
                 Geometric un-letterboxing -> JET colormap overlay -> Base64 encoding.
   - Response Schema:
     {
       "predicted_class": "notumor",
       "confidence": 0.9307,
       "probabilities": {...},
       "gradcam_overlay_base64": "data:image/png;base64,...",
       "gradcam_heatmap_base64": "data:image/png;base64,...",
       "gradcam_panel_base64": "data:image/png;base64,..."
     }

7. SECURITY & PRIVACY MEASURES
--------------------------------------------------------------------------------
1. File Size Protection: Enforced 10MB maximum upload limit.
2. Magic Header & Decoding Validation: Validated with PIL verify() on in-memory buffers;
   does not blindly trust file extensions.
3. Strict Format Whitelisting: Accepts only valid JPEG and PNG files.
4. Non-Executable Storage: Uploaded images are processed entirely in RAM (io.BytesIO)
   and immediately garbage collected. No files are written to disk.
5. Error Sanitization: Python exception stack traces are suppressed in HTTP responses;
   standardized JSON format {"error": "..."} returned to clients.
6. CORS Hardening: Configured for local development origins (localhost:3000, 5173, 8000, etc.)
   rather than open wildcard origins.
7. Privacy: Zero collection or persistence of Patient Health Information (PHI/PII).
